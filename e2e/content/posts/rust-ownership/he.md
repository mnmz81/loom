בעלות (ownership) היא הרעיון המרכזי של ראסט. היא מה שמאפשר לשפה לנהל זיכרון בלי garbage collector ובלי `free` ידני: הקומפיילר בודק בזמן קומפילציה מי אחראי לכל ערך, ומשחרר אותו בדיוק ברגע הנכון.

## שלושת החוקים

1. לכל ערך בראסט יש בעלים (owner) — משתנה שמחזיק אותו.
2. בכל רגע יש לערך בעלים אחד בלבד.
3. כשהבעלים יוצא מה-scope, הערך משוחרר (ראסט קוראת ל-`drop` אוטומטית).

```rust
fn main() {
    {
        let s = String::from("hello"); // s הוא הבעלים של המחרוזת
        println!("{s}");
    } // כאן s יוצא מה-scope והזיכרון משוחרר
}
```

## העברה (Move)

השמה של `String` למשתנה אחר לא מעתיקה את המידע שב-heap — היא מעבירה את הבעלות. המשתנה הישן כבר לא תקף, והקומפיילר לא ייתן להשתמש בו:

```rust
let a = String::from("hi");
let b = a;            // הבעלות עברה ל-b
// println!("{a}");   // error[E0382]: borrow of moved value: `a`
println!("{b}");
```

כך נמנע double free: רק לבעלים אחד מותר לשחרר את הזיכרון.

אותו דבר קורה כשמעבירים ערך לפונקציה — הפונקציה הופכת לבעלים, והערך משוחרר בסופה (אלא אם היא מחזירה אותו).

```rust
fn consume(s: String) {
    println!("{s}");
} // s משוחרר כאן

let name = String::from("Rust");
consume(name);
// name כבר לא תקף כאן
```

## העתקה: `Copy` ו-`clone`

### טיפוסים פשוטים

טיפוסים קטנים שיושבים כולם על ה-stack, כמו `i32`, `bool`, `char` ו-`f64`, מממשים את `Copy`. השמה שלהם מעתיקה את הערך, ושני המשתנים נשארים תקפים:

```rust
let x = 5;
let y = x; // העתקה, x עדיין תקף
println!("{x} {y}");
```

### העתקה עמוקה

כשבאמת צריך שני עותקים של `String` או `Vec`, קוראים ל-`clone()` במפורש. זה עולה הקצאה חדשה, ולכן ראסט לא עושה את זה בשבילכם בשקט.

```rust
let a = String::from("hi");
let b = a.clone();
println!("{a} {b}"); // שניהם תקפים
```

## מה הלאה

להעביר בעלות בכל קריאה לפונקציה זה מסורבל. הפתרון הוא השאלה (borrowing) עם `&` ו-`&mut` — הנושא של הפוסט הבא בסדרה.
