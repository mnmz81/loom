בפוסט הקודם ראינו שהעברת ערך לפונקציה מעבירה את הבעלות. בדרך כלל אנחנו רק רוצים לתת לפונקציה להסתכל על הערך או לשנות אותו, ולקבל אותו בחזרה. בשביל זה יש הפניות (references): במקום להעביר את הערך, משאילים אותו.

## הפניה משותפת: `&T`

`&T` נותנת גישת קריאה בלבד. הבעלות נשארת אצל המשתנה המקורי:

```rust
fn len(s: &String) -> usize {
    s.len()
}

let name = String::from("Rust");
let n = len(&name);
println!("{name} has {n} bytes"); // name עדיין תקף
```

מותר להחזיק כמה הפניות משותפות לאותו ערך בו־זמנית.

## הפניה משתנה: `&mut T`

כדי לשנות ערך מושאל צריך `&mut`, וגם המשתנה המקורי צריך להיות `mut`:

```rust
fn shout(s: &mut String) {
    s.push('!');
}

let mut greeting = String::from("hi");
shout(&mut greeting);
println!("{greeting}"); // hi!
```

## חוקי ההשאלה

בכל רגע מותר אחד מהשניים:

- כמה הפניות `&T` שרק קוראות, **או**
- הפניה `&mut T` אחת בלבד.

בנוסף, הפניה אף פעם לא יכולה לחיות יותר מהערך שהיא מצביעה עליו — אין dangling references.

### למה הקומפיילר מתלונן

זו השגיאה הקלאסית:

```rust
let mut v = vec![1, 2, 3];
let first = &v[0];   // השאלה משותפת
v.push(4);           // error[E0502]: cannot borrow `v` as mutable
                     // because it is also borrowed as immutable
println!("{first}");
```

זה לא סתם קפדנות: `push` עלול להקצות מחדש את הזיכרון של הווקטור, ואז `first` היה מצביע על זיכרון שכבר שוחרר.

### הפתרון

ההשאלה נגמרת בשימוש האחרון בהפניה (Non-Lexical Lifetimes), לא בסוף ה-scope. מספיק לסדר מחדש את הקוד:

```rust
let mut v = vec![1, 2, 3];
let first = v[0];    // i32 הוא Copy, אז מעתיקים ולא משאילים
v.push(4);
println!("{first}");
```

או להשתמש בהפניה לפני ה-`push`, ואז ההשאלה כבר הסתיימה.

## בקצרה

- `&` לקריאה, `&mut` לכתיבה.
- הרבה קוראים או כותב אחד — לא שניהם יחד.
- כשהקומפיילר מתלונן, חפשו הפניה שעדיין בשימוש אחרי שינוי.
