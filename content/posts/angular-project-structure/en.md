[In the previous post](en/posts/angular-install-ng-new/) `ng new my-app` created a project. Most of its files almost never change, but it's worth knowing what each one does before writing code.

Every file here was generated by Angular CLI 22.2's `ng new`, unchanged.

## The tree

```text
my-app/
├── angular.json
├── package.json
├── tsconfig.json
├── tsconfig.app.json
├── tsconfig.spec.json
├── public/
│   └── favicon.ico
└── src/
    ├── index.html
    ├── main.ts
    ├── styles.css
    └── app/
        ├── app.config.ts
        ├── app.routes.ts
        ├── app.ts
        ├── app.html
        ├── app.css
        └── app.spec.ts
```

npm creates `node_modules/` and `package-lock.json`, and the CLI creates `.angular/` (the build cache). You don't edit any of them by hand, and `.gitignore` already excludes `node_modules` and `.angular/cache`. The [project structure docs](https://angular.dev/reference/configs/file-structure) describe every file.

## src/main.ts

The entry point: the first code that runs in the browser.

```typescript
import { bootstrapApplication } from '@angular/platform-browser';
import { appConfig } from './app/app.config';
import { App } from './app/app';

bootstrapApplication(App, appConfig)
  .catch((err) => console.error(err));
```

[`bootstrapApplication`](https://angular.dev/api/platform-browser/bootstrapApplication) takes a root component and a configuration, and renders the component in place of its tag in `index.html`. `src/index.html` has `<app-root></app-root>`, which is exactly the `selector` of `App`. The CLI adds the `<script>` and `<link>` tags at build time, so you don't write them in `index.html`.

## app.config.ts

```typescript
import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';
import { provideRouter } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideRouter(routes)
  ]
};
```

This is where the app-wide providers go: services and features such as the router, HttpClient or animations. [`provideBrowserGlobalErrorListeners`](https://angular.dev/api/core/provideBrowserGlobalErrorListeners) forwards errors nobody caught (the `error` and `unhandledrejection` events on `window`) to Angular's `ErrorHandler`. `provideRouter` turns on the router with the routes from `app.routes.ts`. What a provider is exactly is explained in level 4.

## The root component

```typescript
import { Component, signal } from '@angular/core';
import { RouterOutlet } from '@angular/router';

@Component({
  imports: [RouterOutlet],
  selector: 'app-root',
  styleUrl: './app.css',
  templateUrl: './app.html',
})
export class App {
  protected readonly title = signal('my-app');
}
```

The component is split into three files: the code in `app.ts`, the template in `app.html` and the styles in `app.css`. `app.html` is a sample welcome page, and a line at its top says it's a placeholder. Delete all of it except the `<router-outlet />` at the end, where the router shows pages. `app.spec.ts` checks that the component is created and that the `<h1>` shows `Hello, my-app`.

The file and class names have no suffix: `app.ts`, not `app.component.ts`; `App`, not `AppComponent`. That's been `ng new`'s default since version 20 (the [style guide](https://angular.dev/style-guide) shows this style, e.g. `UserProfile` in `user-profile.ts`). The `--file-name-style-guide=2016` flag brings back the old names.

## app.routes.ts

```typescript
import { Routes } from '@angular/router';

export const routes: Routes = [];
```

The app's route list, empty at first. Routing gets a whole level (level 5).

## angular.json

The CLI settings: how to build, serve and test each project in the workspace. The important part is the `build` target:

```json
"build": {
  "builder": "@angular/build:application",
  "options": {
    "browser": "src/main.ts",
    "tsConfig": "tsconfig.app.json",
    "assets": [{ "glob": "**/*", "input": "public" }],
    "styles": ["src/styles.css"]
  },
  "defaultConfiguration": "production"
}
```

`browser` is the entry point, `assets` copies everything in `public/` as is, and `styles` adds `src/styles.css`, the global styles for the whole app. `build` has two configurations: `production` (the default for `ng build`, with `budgets` that warn when the code grows past 500kB) and `development` (no optimization, with source maps), which `ng serve` uses. The `serve` and `test` targets are defined in the same file. The [angular.json docs](https://angular.dev/reference/configs/workspace-config) list every option.

## The tsconfig files

`tsconfig.json` is the base and the other two extend it: `tsconfig.app.json` for the app code (all of `src/**/*.ts` except `*.spec.ts`), and `tsconfig.spec.json` for tests (with the `vitest/globals` types). Part of the base:

```json
"compilerOptions": {
  "noImplicitOverride": true,
  "noPropertyAccessFromIndexSignature": true,
  "noImplicitReturns": true,
  "noFallthroughCasesInSwitch": true,
  "experimentalDecorators": true,
  "target": "ES2022",
  "module": "preserve"
},
"angularCompilerOptions": {
  "strictInjectionParameters": true,
  "strictInputAccessModifiers": true
}
```

There's no `"strict": true`, because [since TypeScript 6.0](en/posts/typescript-tsconfig/) it's on by default. `strictTemplates`, strict type checking of templates, is missing for the same reason: per the [docs](https://angular.dev/reference/configs/angular-compiler-options) it defaults to `true`. An Angular 21 project still wrote both explicitly.

## public/

Files served as they are: images, fonts, `favicon.ico`. A file `public/logo.svg` is available at `logo.svg`, without `public/` in the path.

### In older versions

Angular 14's `ng new` created a few more files (from a `--dry-run`, shortened):

```text
CREATE v14-app/karma.conf.js (1424 bytes)
CREATE v14-app/src/favicon.ico (948 bytes)
CREATE v14-app/src/polyfills.ts (2338 bytes)
CREATE v14-app/src/test.ts (749 bytes)
CREATE v14-app/src/assets/.gitkeep (0 bytes)
CREATE v14-app/src/environments/environment.prod.ts (51 bytes)
CREATE v14-app/src/environments/environment.ts (658 bytes)
CREATE v14-app/src/app/app.module.ts (314 bytes)
CREATE v14-app/src/app/app.component.ts (211 bytes)
```

`polyfills.ts` loaded zone.js, `environments/` held different settings for development and production, and static files lived in `src/assets/` instead of `public/`. By Angular 19 `polyfills.ts` and `environments/` were gone (zone.js moved to the `polyfills` list in `angular.json`), and `ng generate environments` still [creates the folder](https://angular.dev/tools/cli/environments) if you need it. File names with `.component` stayed until version 19.

And an NgModule-based project, as Angular 19 generated it with `--standalone=false`:

```typescript
// main.ts
import { platformBrowser } from '@angular/platform-browser';
import { AppModule } from './app/app.module';

platformBrowser().bootstrapModule(AppModule, {
  ngZoneEventCoalescing: true,
})
  .catch(err => console.error(err));

// app/app.module.ts
import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { AppRoutingModule } from './app-routing.module';
import { AppComponent } from './app.component';

@NgModule({
  declarations: [AppComponent],
  imports: [BrowserModule, AppRoutingModule],
  providers: [],
  bootstrap: [AppComponent]
})
export class AppModule { }
```

Instead of `bootstrapApplication` and `app.config.ts`, `bootstrapModule` takes a module: `declarations` registers the components, `imports` brings in other modules, and `bootstrap` sets the root component.

## Mistakes beginners make

- **Writing `<script>` tags in `index.html`.** The CLI adds the code itself; libraries and global styles go in through `angular.json` or `import`.
- **Writing `public/` in an image path.** The path is `logo.svg`, not `public/logo.svg`.
- **Looking for `app.module.ts` or `environments/` in a new project.** They're no longer generated.
